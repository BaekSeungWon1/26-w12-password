# 비밀번호 보안 도구 (`26-w12-password`)

## 소개

브라우저 내부에서 비밀번호의 안전성을 실시간으로 진단하고, 암호학적으로 안전한 난수 생성 및 k-익명성 기반 유출 여부를 점검할 수 있는 **비밀번호 보안 점검 & 생성 대시보드**입니다. 모든 분석과 해싱 처리를 클라이언트(브라우저) 내부에서만 수행하여 사용자의 민감한 비밀번호가 외부로 유출되지 않도록 설계했습니다.

## Vite 프로젝트 직접 구성 경험

1. **템플릿 저장소와의 차이점:** 지난주까지는 `package.json`, `vite.config.js`, `src/` 등이 미리 구성된 저장소를 받았지만, 이번에는 빈 저장소에서 `npm create vite@latest .`로 직접 React 프로젝트 환경을 구축했습니다. 프레임워크와 언어(TypeScript 대신 JavaScript), 린터(Oxlint)를 직접 선택하고 `vite.config.js`의 `base: './'` 설정과 `gh-pages` 배포 스크립트를 수동으로 구성하면서 프로젝트 초기 설정 구조를 정확히 이해할 수 있었습니다.
2. **파일 덮어쓰기 및 `.gitignore` 보강:** `create-vite` 실행 시 기존 `README.md`와 `.gitignore`가 기본 파일로 덮어써지는 것을 확인하고, 미리 백업된 `README.template.md`로 회고 양식을 복구했습니다. 또한 기본 `.gitignore`에는 `*.local`만 차단되어 있어, 실수로 API 키나 비밀 설정이 담긴 `.env` 파일이 GitHub에 커밋되는 사고를 막기 위해 `.env`, `.env.*`, `!.env.example` 규칙을 직접 추가했습니다.

## 나의 AI 기획·구현 과정

1. **AI 협업 방식:** Gemini 웹에서 프로젝트 요구사항과 보안 체크포인트, UI 구조를 먼저 상세히 기획한 뒤, 작성한 기획 프롬프트를 Antigravity IDE Chat에 전달하여 코드를 구현하는 방식을 사용했습니다.
2. **비밀번호 강도 기준:** 길이(8자 이상, 12자 이상 권장), 영문 대문자·소문자·숫자·특수문자 포함 여부를 점수화하고, `1234`, `qwer`, `password` 같은 흔한 패턴이나 동일 문자 3회 이상 반복이 감지되면 감점하도록 기준을 세웠습니다.
3. **문제 해결 과정:** PowerShell 실행 정책 제한으로 `npm` 명령어가 차단되는 오류가 발생했으나, `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` 명령어로 사용자 권한을 허용해 해결했습니다. 또한 `package.json` 수정 중 중복 블록 문법 오류를 정리하여 정상적으로 빌드 및 실행을 마쳤습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. **`crypto.getRandomValues()`를 사용해야 하는 이유:** `Math.random()`은 의사난수(PRNG) 방식으로 내부 시드 값을 예측할 수 있어 공격자가 생성된 비밀번호를 추측할 위험이 있습니다. 반면 Web Crypto API의 `crypto.getRandomValues()`는 운영체제가 제공하는 암호학적으로 안전한 난수 생성기(CSPRNG)를 사용하므로 예측 불가능한 안전한 비밀번호를 만들 수 있습니다.
2. **Network 탭 검증 결과:**
   - 실제 전송된 요청 주소: `https://api.pwnedpasswords.com/range/5BAA6`
   - 테스트 비밀번호(`password`)의 원본 문자열이나 40자리 SHA-1 해시 전체는 전송되지 않았으며, 해시의 맨 앞 5글자(`5BAA6`)만 서버로 전송되고 나머지 35글자 대조는 브라우저 내부에서 수행되는 것을 확인했습니다.
3. **k-익명성의 한계:** 서버는 비밀번호 원본과 전체 해시는 알 수 없지만, 요청이 들어온 **해시 앞 5글자(Prefix)**, 요청자의 **IP 주소**, **요청 시각**, 그리고 응답 데이터 크기 등을 확인할 수 있으므로 네트워크 수준에서 완전히 익명화되는 것은 아닙니다.

## 나만의 확장 기능

- **`Add-Padding: true` 헤더 적용:** HIBP API 요청 시 응답 크기를 통해 실제 유출 목록 개수를 유추하는 측면 채널 분석을 방지하기 위해 `Add-Padding` 헤더를 적용하고, 응답에서 유출 횟수가 `0`인 가짜(패딩) 항목을 필터링하도록 구현했습니다.
- **AES-GCM 암호화 메모 금고:** 사용자가 입력한 마스터 비밀번호로부터 PBKDF2로 암호화 키를 파생해 Web Crypto API의 AES-GCM 방식으로 메모를 암호화·복호화할 수 있는 금고 탭을 추가했습니다.
- **다크/라이트 테마 전환:** 사용자 환경에 맞게 어두운 배경(다크 모드)과 밝은 배경(라이트 모드)을 즉시 전환할 수 있는 UI 토글 기능을 구현했습니다.
